# AI フレームワーク研究アーカイブ

arXiv に公開され、かつトップカンファレンス群で発表された **フレームワーク研究** を収集・分類したアーカイブです。

**公開サイト: https://miki0902.github.io/TestT/**

## 収録条件

以下の3条件をすべて満たす研究を対象とします。

1. **arXiv に論文が公開されている**
2. **トップカンファレンス群に採択されている**（本会議・ワークショップの双方を対象。区別は `venue_type` に記録）
3. **フレームワーク研究である** — 汎用的なアーキテクチャ・手法・パイプラインを提案しているもの

著者・所属による制約はありません（企業・大学・個人を問わず対象）。

### 対象カンファレンス

NeurIPS / ICML / ICLR / CVPR / ICCV / ECCV / ACL / EMNLP / NAACL / AAAI / IJCAI / KDD / SIGGRAPH / CoRL / RSS

## タグ定義

| タグ | 内容 |
|---|---|
| アーキテクチャ提案 | 新しいモデル構造・モジュール（Attention 変種、MoE、SSM 等） |
| 学習・最適化手法 | 事前学習／ファインチューニング／RL の手法、性能向上系 |
| モデル圧縮・効率化 | 蒸留、量子化、プルーニング、KV キャッシュ、高速推論 |
| データ構築・フィルタリング | データ選別・合成・キュレーションのパイプライン |
| 推論時フレームワーク | プロンプト戦略、デコーディング、エージェント、ツール利用 |
| 検索拡張・記憶 | RAG、長期記憶、外部知識統合 |
| 評価・解析フレームワーク | 評価パイプライン、解釈可能性 |
| 基盤モデル | 基盤モデル本体の構築・公開を伴う研究 |
| 世界モデル・具現化AI | 世界モデル、ロボティクス、シミュレーション |
| マルチモーダル・生成 | 画像・動画・音声・音楽の理解／生成 |
| コード・科学応用 | コード生成、数学、科学領域への応用 |
| 安全性・アラインメント | 安全性、アラインメント、頑健性 |

タグは複数選択可です。

## ディレクトリ構成

```
.
├── README.md          # 本ファイル（運用ルールとタグ定義）
├── INDEX.md           # 全収録論文の一覧表（自動生成・手で編集しない）
├── papers/
│   └── <年>/
│       └── <arxiv_id>-<slug>.md   # 正となるデータ
├── docs/              # GitHub Pages で公開される静的サイト
│   ├── index.html     # 検索・タグ絞り込み付きの一覧
│   └── papers.json    # 自動生成・手で編集しない
└── tools/
    └── build_site.py  # papers/ から INDEX.md と docs/papers.json を生成
```

### 更新手順

論文ファイルを追加・編集したら、リポジトリのルートで以下を実行する。

```
python3 tools/build_site.py
```

`INDEX.md` と `docs/papers.json` が再生成される。スクリプトは frontmatter のキー欠落・未定義タグ・`arxiv_id` の重複を検出して警告する。push すると GitHub Pages に反映される。

## 論文ファイルの書式

各ファイルは YAML frontmatter と本文で構成されます。

```markdown
---
arxiv_id: "2401.12345"
title_ja: "日本語タイトル"
title_en: "English Title"
authors_org: "所属組織"
year: 2024
venue: "NeurIPS 2024"
venue_type: "本会議"        # 本会議 / ワークショップ
tags: ["アーキテクチャ提案", "モデル圧縮・効率化"]
summary_line: "一行要約（INDEX.md に転記される）"
arxiv_url: "https://arxiv.org/abs/2401.12345"
code_url: ""
project_url: ""
added_at: "2026-07-27"
---

## 研究サマリー

**課題** — 何が問題だったのかを2〜3文で。

**手法** — どう解いたのかを2〜3文で。

**成果** — 何ができるようになったのか、実用上どう効くのかを2〜3文で。

## 公開情報

- **論文**: [タイトル](URL)
- **ブログ**: [タイトル](URL) ※あれば
- **GitHub**: [リポジトリ名](URL) ※あれば
- **学会**: 学会名・発表形式
- **X投稿**: (URL) ※あれば

## ポイント

- 箇条書きで3〜5点
```

### 記述方針

- 研究サマリーは **課題・手法・成果の3点構造** で書く
- 専門用語はなるべく避け、分野外の読者でも読める表現にする。避けられない用語には短い言い添えを付ける
- `summary_line` は1文（40字程度）で、その研究が何をしたかを端的に表す

## 運用

- 初回は過去3年分（2023年以降）を対象にバックフィルを実施
- 以降は毎週、新規採択・新規公開分を差分追加
- 重複排除は `arxiv_id` をキーに `papers/` 配下を走査して判定
